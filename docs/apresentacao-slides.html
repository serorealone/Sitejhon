Parte 1 — Guilherme

Enunciado e Requisitos Funcionais

Substituir o controle manual de uma pequena loja por um sistema confiável e integrado.

Requisitos Funcionais (PDF)

  • Cadastrar categorias e produtos;
  • Consultar produtos por nome ou categoria;
  • Registrar entradas e saídas de estoque;
  • Atualizar a quantidade disponível automaticamente;
  • Exibir lista de produtos com estoque baixo;
  • Consultar o histórico de movimentações por produto.

Regras de Negócio Críticas

  • Todo produto deve pertencer a uma categoria existente;
  • Bloquear saídas maiores que o estoque disponível;
  • Bloquear movimentações com quantidade <= 0;
  • Registrar produto, tipo, quantidade, data e usuário em cada movimentação.
Modelo normalizado até a 3ª Forma Normal (3FN), sem dados repetidos.

Parte 2 — Antonio

Modelo Lógico, Físico e Restrições SQL

Integridade garantida diretamente no SGBD (database/sqlite/01-schema.sql).

Chaves e Integridade Referencial

  • PK (id): identificador único e imutável em todas as tabelas;
  • FK (categoria_id, produto_id, usuario_id): com ON DELETE RESTRICT — impede apagar categoria com produto ou produto com histórico;
  • UNIQUE: usuarios(email), categorias(nome) e produtos(sku);
  • NOT NULL: campos obrigatórios protegidos contra nulos.
CREATE TABLE "movimentacoes" (
  "id" INTEGER PRIMARY KEY AUTOINCREMENT,
  "produto_id" INTEGER NOT NULL,
  "tipo" TEXT NOT NULL CHECK ("tipo" IN ('ENTRADA', 'SAIDA')),
  "quantidade" INTEGER NOT NULL CHECK ("quantidade" > 0),
  "saldo_resultante" INTEGER NOT NULL CHECK ("saldo_resultante" >= 0),
  "usuario_id" INTEGER NOT NULL,
  FOREIGN KEY ("produto_id") REFERENCES "produtos"("id") ON DELETE RESTRICT
);
CHECK no físico: também aplicado em produtos (quantidade >= 0, preços >= 0) e usuarios (papel).

Parte 4 — Braian

Alertas, Consultas SQL e Segurança

5+ consultas SQL com JOIN, COUNT, SUM, filtros e proteção contra SQL Injection.

Telas e Consultas (03-consultas.sql)

  • Alertas: produtos com estoque baixo ou zerado;
  • Histórico: movimentações por produto com JOIN em produtos, categorias e usuários;
  • Consolidado por categoria: LEFT JOIN + COUNT + SUM;
  • Ranking mais movimentados: GROUP BY + SUM(CASE ...).
SELECT c.nome AS categoria,
       COUNT(p.id) AS total_produtos,
       COALESCE(SUM(p.quantidade), 0) AS unidades
FROM categorias c
LEFT JOIN produtos p ON p.categoria_id = c.id
GROUP BY c.id, c.nome
ORDER BY unidades DESC;
Segurança e Atomicidade: Consultas parametrizadas (?) contra SQL Injection e movimentações dentro de transação ($transaction).
